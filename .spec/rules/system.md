# LumioProfile 的产品约束

- 插件不得成为 Engine、Games 或业务平台的强制运行依赖；未安装、未装配和关闭状态不得导致宿主启动失败或游戏语义变化。
- 接入方持有不依赖插件包的轻量观测契约与空槽位；插件仅从可选入口注入实现。普通构建的类型检查和模块解析不得要求可选插件存在，类型导入也不能例外。
- 安装、导入和 Agent 连接不得隐式开启采集；Debug 与 Release 都需要明确启用，Release 不得因普通客户端参数开放诊断能力。
- 运行时关闭判断必须先于时钟读取、诊断参数构造、记录与跨语言调用；不得把 no-op 声称为零开销。完全裁剪需验证实际产物，不得与运行时关闭混为一谈。
- 本仓只提供可选观测能力；是否接入及如何埋点由接入方负责，不自动改写、代理或全量插桩游戏函数。
- 采集结果不得参与玩法决策、资源结算、输入排序、目标 tick、权威调度或预测判定；不得改变 Lumio 的 20Hz 服务器权威与 GAS 预测边界。
- 玩法线程不得等待采集上传、导出或查询；缓冲压力必须在诊断链路内处理，不能反压玩法队列。
- 普通 Trace 满时保留已有记录、丢弃新详细事件；循环覆盖必须显式选择。缺失不能隐瞒，缓冲压力不能静默改变已接受的采集策略。
- 不得直接相减未经校准的跨时钟域时间；不得把区间墙钟耗时或 CPU 采样当作精确 CPU 执行时间，不得把 WebGL 提交、下一次 RAF 或 GPU 查询完成当作物理屏幕呈现。
- 缺失、丢弃、未支持、未开启和未观察到终点必须显式表达，不能用零耗时、成功或取消代替未知。
- `sources/` 只作为只读参考；不得修改其他仓库或 Games 的 `.engine` 缓存来完成本仓的设计整理。
