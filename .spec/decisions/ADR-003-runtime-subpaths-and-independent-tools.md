# ADR-003：一个采集包带三个环境子入口，工具与 Unity 原生包独立

状态：Accepted

日期：2026-10-16

## 背景

浏览器、PuerTS 与服务器需要共用 TS 观测契约，同时隔离环境依赖。分析工具不应进入游戏产物；Unity 原生适配也不应成为浏览器或服务器的依赖。用户已明确选择一个采集包带三个环境子入口，工具包和 Unity 原生包独立。

## 决策

1. 采集核心与浏览器、PuerTS、Node 适配放在同一个可选采集包，通过三个独立子入口接入，采用同一采集 SDK 版本。
2. 采集协调、导出转换、Perfetto 查询、CLI 与后续 MCP 包装放在独立工具包，运行于开发机或独立分析服务，不进入宿主运行依赖图。
3. Unity 原生时钟、批量桥接与原生 Profiler 数据适配作为独立可选 Unity 包。TS 侧 PuerTS 子入口通过注入桥接契约使用这些能力，不由 TS 根入口自动加载原生包。
4. 采集包的根入口及公共导出不能把所有平台适配相互拉入。浏览器与 PuerTS 子入口不依赖 Node 环境；独立工具包可以依赖采集协议，采集端不得反向依赖工具包。
5. 宿主无依赖契约继续遵循 [ADR-002](ADR-002-host-contract-and-optional-injection.md)，不新增强制 API 包。环境统一通过语义契约和能力协商实现，不承诺所有平台具备相同原生数据源。

候选名称为 `@lumio/profile`、`@lumio/profile-tools` 与 `com.lumio.profile`。本决策确认包边界与发布粒度，不表示这些包已注册或发布，也不冻结 SDK 签名、子入口映射、协议编码、兼容版本范围或数值预算。当前仅维护文档，不实施 SDK、脚手架或消费者改造。

## 替代方案

| 方案 | 取舍 |
| --- | --- |
| 采集、分析、原生适配全部放入一个包 | 扩大宿主依赖，难以独立部署工具，也使平台依赖更容易泄漏 |
| 浏览器、PuerTS、Node 分别发布采集包 | 可以独立升级，但首期增加契约和版本组合的维护成本 |

## 影响

三端采集适配随同一个 SDK 发布，需要验证子入口各自的依赖闭包。工具包和 Unity 包可以独立发布，但要声明支持的契约与协议范围；不能仅凭三个包的版本号相近就认为兼容。

单包安装体积与最终宿主产物体积不同，验收同时检查模块图、部署产物和实际加载。未选择的环境适配不得进入运行路径，尤其不能从浏览器入口解析 Node 内置模块。

## 重新评估条件

如果出现实际的独立发布需求、平台适配依赖或安装体积不可接受，再评估拆分环境包。重新拆包仍需维持无插件构建、默认 Off、独立分析部署及宿主语义不变的边界。
