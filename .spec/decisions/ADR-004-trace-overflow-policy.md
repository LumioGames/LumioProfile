# ADR-004：普通 Trace 保留已有记录，循环覆盖显式选择

状态：Accepted

日期：2026-10-16

## 背景

从一次操作开始的有限采集需要保留起点证据；偶发问题则可能需要最近窗口。缓冲有固定上限，不能通过无限分配、重传或阻塞玩法来保证记录完整。用户已确认普通 Trace 默认保留已有记录、满时丢新详细事件，循环覆盖作为显式选项。

## 决策

1. 普通 Trace 默认保留已有记录，容量不足时拒绝新的详细记录；排出并释放容量后可以继续记录，实际缺口必须可见。
2. 循环 Trace 必须明确选择，按完整批次覆盖最旧详细记录，保留最近窗口。不得因缓冲压力静默切换到循环策略。
3. 两种模式均为质量信息和已开始区间收尾预留有限空间，但不承诺关键记录绝不丢失。质量信息无法可靠维护时，终止该来源详细采集并报告原因，不把残留数据标成完整。
4. 字典、未闭合区间、排出队列、待确认批次和质量信息均计入总预算。运输与导出有界；压力不得反压玩法或改变输入、权威调度、预测与资源结算。
5. 未开启/过滤、缓冲丢弃、循环覆盖、运输缺失、导出截断和来源尾部未知分别表达。丢失端点不得补造区间，不完整样本不得冒充总体统计。

本决策只确认缓冲策略及其质量边界。字段名、编码、容量、预留比例、排出阈值、重传参数和校准参数仍为设计约定；当前不实现采集器或测试宿主。

## 替代方案

| 方案 | 取舍 |
| --- | --- |
| 所有 Trace 默认循环覆盖 | 能保留最近现场，但可能覆盖已主动采集的操作起点 |
| 缓冲满后阻塞或无限扩容 | 会影响宿主行为或突破资源预算，不符合可选插件边界 |
| 永久停止记录且不报告缺口 | 无法区分完整采集和过早截断，也无法利用后续释放的容量 |

## 影响

普通 Trace 可能产生中间缺口，循环 Trace 可能丢失区间起点；分析必须依赖明确身份和质量信息重建，而不是盲目配对 begin/end。预留收尾空间只能降低损失，不能证明全部记录完整。

接入方在准备采集时看到实际接受的策略；导出与 Agent 结果保留相同配置和覆盖范围。详细记录满时不会自动开启 Stats；已有 Stats 仍按自身显式配置运行。

## 重新评估条件

若实际场景显示默认策略不能保留主要排障证据，可以评估新的显式预设或优先级策略，但不能隐藏丢弃、自动改变已接受配置或放宽宿主不受反压的边界。
