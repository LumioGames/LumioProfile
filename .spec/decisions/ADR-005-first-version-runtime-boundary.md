# ADR-005：第一版有限采集与可复查分析

状态：Accepted

日期：2026-10-16

## 背景

用户已授权在 lumio-profile 实现第一版闭环，明确只改本仓、验证无插件/Off/开销，Unity/PuerTS 未实测部分如实标明。协议与工具需要一组可独立验收的具体实现边界。

## 决策

采用 TypeScript 采集核心及三个隔离入口；热路径用固定数值/字符槽。第一版采集中保留有界数据，停止后通过显式控制通道每批 64 条排出；原始包用可校验 JSON，工具用 protobufjs 生成原生 Perfetto。固定官方 Trace Processor v58.2，Agent 与 UI 共享版本化 SQL。

控制服务只监听回环地址，显式令牌和浏览器 Origin。不隐式开启 CPU/GPU、不自动注入宿主。Unity 原生包仅实现条件编译的时钟/主线程调度桥接；真实 Unity、PuerTS 和 IL2CPP 支持需要另外的运行证据。

停止宽限为 0，未闭合区间保持缺失。采集中持续排出、原始 Protobuf、压缩、重连续传、漂移拟合、远程服务部署与原生采样不纳入当前已交付能力。具体限制和实测结果记录在第一版运行能力文档。

## 替代方案

直接在三端生成完整 Perfetto 增加采集侧复杂度；先做长期在线平台会扩大部署范围；先做全量 Unity Profiler 接入需要当前缺少的目标运行环境。有限采集先验证同一证据从采集到查询的闭环。

## 影响

普通 Trace 满后直至停止仍可能丢新；循环覆盖显式选择。容量与模型有明确上限，但配置存储预留不等于 VM 精确内存，候选性能预算必须独立验证，不能以功能测试替代。

## 重新评估条件

目标场景需要更长窗口、更高事件率、稳定远程采集或已具备 Unity 实测环境时，可扩展传输和适配器；不得改变 Off、可选依赖、业务不反压和证据质量边界。
