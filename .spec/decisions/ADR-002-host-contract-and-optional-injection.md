# ADR-002：宿主持有无依赖观测契约，可选注入实现

状态：Accepted

日期：2026-10-16

## 背景

接入方需要在未安装 LumioProfile 时正常构建运行，并在 Debug、Release 关闭采集时避免计时、参数构造与跨语言采集成本。浏览器、Unity + PuerTS 和独立服务器应复用观测语义，分别适配环境能力。用户已确认以下接入原则，并要求写入设计与使用指引；本决策不授权实现。

## 决策

1. 接入方持有零外部依赖的轻量观测声明与可选槽位，可以复用 Engine 提供的契约。LumioProfile 作为结构兼容的可选实现，由独立诊断入口注入。普通入口不依赖该包；不要求所有消费者安装单独的 API 包。
2. 普通构建的类型检查与模块图排除可选集成模块。只有选择诊断能力的构建才解析插件及其适配器。类型导入、动态导入或条件导入本身都不能证明包不存在时能构建。
3. Stats 与 Trace 使用独立可选写入槽位。Off 时槽位为空，热路径先判断，再构造诊断参数、读取时钟或写入；不以空方法或包装回调代替此保证。PuerTS 的关闭判断留在 JS 侧。
4. 编译能力与运行状态分离。Debug、保留诊断能力的 Release 都默认 Off；是否保留能力由接入方决定。运行时 Off 允许有限判断和静态元数据成本，不声称绝对零。完全裁剪需要构建产物验证，裁剪后的能力不能远程开启。
5. 共用 TS 语义契约描述同步区间、阶段事件、因果关联与有界统计；适配器负责时钟、缓冲、排出和原生来源。各执行上下文独立实例化，不跨 Worker 传递 writer 对象。通用接口不依赖浏览器、Node 或 Unity 全局 API。
6. 观测接口与采集控制分离。控制流先协商能力，再准备、启用、查询状态、停止与导出；启停只管理诊断资源，不改变宿主调度。停止撤销新写入入口，已开始区间保持原会话身份，有界收尾后把缺失端点标为不完整。
7. 用无插件构建、关闭路径计数、裁剪产物检查、跨环境契约验证及对照测量证明上述保证；没有实测前不宣称性能指标已达成。

具体方法签名、契约版本协商、发布入口、构建适配、编码与数值预算仍待讨论。用法见 [接入使用指引](../knowledge/standards/integration-guide.md)。

## 替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 业务代码直接导入可选插件的 API 或类型 | 包不存在时可能在类型检查或模块解析阶段失败 |
| 强制所有项目安装一个小型 API 包 | 把可选能力转成所有消费者的必需构建依赖 |
| 始终调用 no-op collector | 仍有调用与参数求值成本；回调包装还可能产生闭包 |
| 只用运行时环境变量关闭 | 不证明代码、依赖、分支或原生桥接已从产物消失 |
| 自动代理全部游戏函数 | 超出插件边界，增加开销与语义风险，接入方失去观测粒度选择 |

## 影响

接入方承担可选入口、构建选择及语义埋点；插件提供协议说明、适配实现与契约验证方法。宿主本地声明需要版本和兼容性校验，不能因结构类型相似就默认语义兼容。

Off 与完全裁剪有不同性能保证。保留远程控制入口会有固定成本，必须计入 Off 基线；未安装和裁剪构建无法临时恢复采集。启用采集仍有测量成本，需独立限额与报告。

## 重新评估条件

若宿主契约维护产生实际兼容问题，再评估契约分发方式，但不得悄悄引入强制插件依赖。若某个构建环境无法可靠裁剪，只能报告其运行时 Off 保证，或另行设计显式构建步骤，不能降低「完全裁剪」的验证标准。
