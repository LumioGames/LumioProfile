# ADR-006：紧凑变长槽位、持续排出、有界外推校准与可选自动采集源

状态：Accepted

日期：2026-11-16

## 背景

第一版（`b5d56cb`）在接入 NextWorld 实测与仓库复评中暴露出长时与重负载采集瓶颈：

1. 每条记录固定预留 1024 bytes，8MiB 仅能存 8162 条（60fps × 10 区间约 6.5 秒即满），且采集中不排出、单服务仅允许 4 场。
2. 跨场区间令牌每场从 1 重新计数，旧会话迟到 `end` 重读 `host.trace` 时会误关新会话区间；到期判断晚于序号自增产生伪缺口。
3. 停止按来源串行分页，忙主线程分页期间其他线程继续运行至超时；部分事件超出 1500ms 校准窗口时整条来源退回本地时间轴。
4. 缺少浏览器长任务/LoAF/rAF 与 Node GC/CPU 栈采样等自动数据源；分析存在 $O(N^2)$ 父子扫描与展开运算符栈溢出。

## 决策

保留 [ADR-001](ADR-001-optional-plugin-and-perfetto.md) 至 [ADR-004](ADR-004-trace-overflow-policy.md) 的全部可选依赖、默认 Off、不反压玩法与质量边界，对 [ADR-005](ADR-005-first-version-runtime-boundary.md) 的容量、传输与采集边界升级如下：

1. **会话代次令牌与非严格 LIFO 恢复**：同步与可选异步区间（`beginAsync`/`endAsync`）令牌高位编码会话代次，跨会话迟到 `end` 安全忽略且不污染新会话质量；内层漏 `end` 时弹出未闭合内层并标 `partial`，保持后续区间父子树干净。期限与字段校验先于序号提交与环形块淘汰。
2. **紧凑槽位与持续排出**：数值列固定 64 bytes，文本改为环形变长 UTF-16 池（均摊 16 bytes/槽，总计 80 bytes/槽，8MiB 约 10.4 万条）。控制通道新增幂等确认式 `drain(ackSeq, limit)`，采集中后台分批排出并释放已确认槽位；导出后自动释放服务内存，取消每进程 4 场硬限制。
3. **两阶段并发停止与有界漂移外推**：`stop` 先并发停止全部来源，再执行停后尾部校准样本采集，最后带单页重试拉取快照并支持 `pull` 单来源补拉。超出直接窗口但在 `maxExtrapolationMs` 内的同代次时钟事件按最近样本有界漂移放大不确定度保留在共享时间轴；无法对齐时在 `domainDiagnostics` 与 `manifest.json` 明确记录退回原因。
4. **显式可选自动数据源**：Off 零开销不变；仅在 `collectors` 显式请求时按环境能力开启浏览器 `raf`、`longtask`、`long-animation-frame`、JS Self-Profiling（需 `Document-Policy: js-profiling`）及 Node `gc`、进程内 `node:inspector` V8 CPU 采样（零网络端口），统一校准至同一 `.pftrace` 时间轴并保留 `.cpuprofile` 附件。
5. **诚实边界维持不变**：收尾宽限固定为 0（立即截止、代次隔离拒绝迟到结束）；GPU 计时、物理屏幕呈现与真实 Unity/PuerTS/IL2CPP 运行验证仍属未实现或未验证范围。

## 替代方案

- 在热路径直接做字符串哈希驻留或实时压缩：增加热路径分支和哈希冲突复杂度；变长环形 UTF-16 池配合零文本快速路径已将容量提升约 12.8 倍且无堆分配。
- 无条件开启浏览器/Node 采样器：违反默认 Off 与性能对照隔离原则，因此保持 `collectors` 显式按需启用。

## 影响

8MiB 单线程静态缓冲即可覆盖约 85 秒中等密度游戏埋点，配合持续排出可支撑数分钟连续采集；忙主线程下多来源保持共享时间轴且误差区间透明放大；单服务进程可常驻连续采集。

## 重新评估条件

当需要跨机器远程加密汇聚、二进制批次传输压缩、WebGL GPU timer query 或具备真实 Unity/PuerTS 运行时验证环境时，再另立 ADR 扩展。
